# Design — 001 Create and list in-memory tasks

## Decisions

- Tasks live in a `TaskStore` object held on `app.state.task_store`, reached by endpoints through a FastAPI dependency `get_task_store(request)`. One store per app object, created when `main` builds the app; nothing is module-global inside `tasks/`. This gives tests a clean seam: replacing `app.state.task_store` with a fresh `TaskStore()` is exactly what a restart does to the data (AC-001.6, AC-001.8). Persistence later swaps the store implementation behind the same dependency.
- The store keeps a `list[Task]` (insertion order is creation order, AC-001.5) guarded by a `threading.Lock`, because FastAPI runs sync endpoints in a thread pool. No upper bound on count (A7).
- `id` is `str(uuid.uuid4())`, generated by the store; any client-sent `id` (or any other unknown field) in the request body is ignored, never echoed (A6, AC-001.7).
- `due_date` is validated explicitly (strict string, regex `^\d{4}-\d{2}-\d{2}$`, then `datetime.date.fromisoformat`) instead of relying on Pydantic's `date` type, because Pydantic's lax `date` parsing also accepts Unix timestamps and date-time strings, which A2 rules out (AC-001.4). Past dates are accepted (A3).
- `title` is a strict string (no coercion of numbers/booleans), length 1..200 counted in Python characters, and must contain at least one non-whitespace character; it is stored exactly as sent, not trimmed (A4, AC-001.3).
- Errors use FastAPI's standard `422` validation body (A5); no custom exception handler.
- No new environment variable, port or probe: the GitOps entry is unchanged. In-memory state means each replica has its own list; the spec's non-goals accept this (no sharing between instances).
- No ADR: the in-memory store is a feature-local, deliberately temporary choice.

Signatures:

```python
# models.py
class TaskCreate(BaseModel):
    title: StrictStr = Field(min_length=1, max_length=200)   # + validator: title.strip() != "" else ValueError
    due_date: StrictStr | None = None                         # + validator: regex + date.fromisoformat -> datetime.date

class Task(BaseModel):
    id: str
    title: str
    due_date: datetime.date | None    # serialised as "YYYY-MM-DD" or null

# store.py
class TaskStore:
    def create(self, title: str, due_date: datetime.date | None) -> Task: ...
    def list(self) -> list[Task]: ...   # copy, creation order

# router.py
def get_task_store(request: Request) -> TaskStore: ...   # request.app.state.task_store
router = APIRouter()
@router.post("/tasks", status_code=201, response_model=Task)
@router.get("/tasks", response_model=list[Task])
```

## Contract

All bodies are `application/json`.

### `POST /tasks`

Request body (JSON object):

| Field | Type | Required | Rule |
|---|---|---|---|
| `title` | string | yes | 1 to 200 characters, at least one non-whitespace character; stored as sent (not trimmed) |
| `due_date` | string `YYYY-MM-DD` or `null` | no | must be a real calendar date; omitted or `null` means no due date; past dates allowed |

Unknown fields (including `id`) are ignored.

`201 Created`:

```json
{"id": "3f2b8c1e-5d7a-4e0b-9c61-2a4f8d9e0b17", "title": "Write report", "due_date": "2026-12-01"}
```

- `id`: non-empty opaque string (currently a UUID4; clients must not rely on the format), unique per task.
- `due_date`: `"YYYY-MM-DD"` or `null` (AC-001.2).

`422 Unprocessable Entity` (FastAPI standard body), no task is created:

```json
{"detail": [{"type": "string_too_long", "loc": ["body", "title"], "msg": "...", "input": "...", "ctx": {"max_length": 200}}]}
```

- Every error item's `loc` ends with the offending field name: `["body", "title"]` (AC-001.3) or `["body", "due_date"]` (AC-001.4). Testers assert on `loc[-1]`, not on `type` or `msg` texts.
- Cases that answer 422 naming `title`: missing (`type` `missing`), not a string (`string_type`), `""` (`string_too_short`), only whitespace (`value_error`), more than 200 characters (`string_too_long`).
- Cases that answer 422 naming `due_date`: not a string or null (`string_type`), not matching `YYYY-MM-DD` such as `"01.12.2026"`, `"tomorrow"`, `"2026-12-01T00:00:00"` (`value_error`), well-formed but no such date such as `"2026-02-30"` (`value_error`).
- A body that is not a JSON object answers 422 with `loc` `["body"]` (framework default).

### `GET /tasks`

`200 OK`: bare JSON array of every task created since the service started, oldest first, each exactly as returned by its `POST` (AC-001.5, AC-001.7). Empty list `[]` when none (AC-001.6, AC-001.8). No query parameters.

```json
[{"id": "...", "title": "A", "due_date": null}, {"id": "...", "title": "B", "due_date": "2026-12-01"}]
```

### Test seam

- In-process tests get a fresh, empty store (equivalent to a service restart, AC-001.8) with `app.state.task_store = TaskStore()` (import `TaskStore` from `taskboard15_api.tasks`), for example in a `conftest.py` fixture.
- Smoke tests (AC-001.1, AC-001.5 marked smoke) run against the deployed URL; they create `smoke-<uuid>` titles, are `@pytest.mark.writes`, and assert their own tasks appear in order within the list rather than that the list equals exactly their tasks. The read-only smoke check is `GET /tasks` answering `200` with a JSON array.

## Data

In memory only: `list[Task]` inside `TaskStore`, lost on restart (AC-001.8). No migration.
